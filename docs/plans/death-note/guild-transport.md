# Transport de guilde Forever — 5 novembre 2026

Objectif : brancher le protocole Guild/Protocol existant aux messages natifs, sans mélanger registre personnel, cache partagé et démonstration. L'utilisateur dispose d'un deuxième membre pour les essais.

Sources du client 1.60.1.70790 : commit eac30af597e5aaa43a60f6675ef5fdcea100375f, ChatInfoDocumentation/ChatConstantsDocumentation (C_ChatInfo, CHAT_MSG_ADDON, retours **énumérés**, pas booléens), GuildInfoDocumentation (MemberExistsByName, événements de guilde), ClubDocumentation (GetGuildClubId/GetClubInfo), UnitDocumentation (UnitFullName). Blizzard_Communities.toc charge une surcharge Camelot. Le registre complet de membres peut contenir des noms |K ; il ne sera pas décodé. L'expéditeur vient du transport GUILD et les identités sont vérifiées par MemberExistsByName, avec garde sur les valeurs protégées. Identité de guilde issue du club réel ; jamais le seul nom de la guilde ni un ID fictif.

Modules : codec de données borné sans exécution Lua ; découpage/réassemblage ; Channel injecté pour tester deux clients ; contexte Forever et file d'envoi native ; cache de sessions de guilde dans un champ additionnel du profil format 1 ; branchement à la vue réelle. Une session sauvegarde aussi les revendications concurrentes, pas seulement les récompenses acceptées. Les états personnels lu/remercié ne partent jamais sur le réseau.

Contrats : canal GUILD uniquement, préfixe versionné, message lié à la guilde et à l'expéditeur réel. Refuser source=demo. Enveloppes hello/state/ack/test ; accusé distinct du simple succès de l'API d'envoi. Rattrapage au démarrage et sur demande, fusion idempotente, diffusion des changements coalescée. Débit et mémoire bornés, expiration des fragments, échec explicite au-delà des limites existantes (128 incidents/128 revendications par session, pas de pagination dans cette tranche). Ne pas prétendre à une preuve serveur des meurtres ou de l'auteur original de chaque fait relayé : le modèle reste un registre attesté par les membres.

Cycle : activation explicite /srsync activer (préférence conservée), arrêt /srsync arreter ; changement de guilde, identité inaccessible ou restriction = pas d'envoi, purge de la file d'une ancienne guilde. /srsync test échange uniquement un signal de diagnostic et son accusé, sans incident fictif dans le vrai registre. Test de rattrapage/faits avec clients injectés ; test réel à deux membres pour le transport et les accusés. La collecte réelle d'incidents reste un chantier séparé.

Préservation : ne pas exporter automatiquement le registre personnel local:forever, les exemples, les préférences ou les diagnostics PvP/chat. Préserver un cache invalide/futur et signaler l'impossibilité de l'ouvrir. Les cartes et portraits gardent leur composition. Nouveau texte d'état seulement, pas de nouvelle maquette.
